# NOTAM Reader

PWA לקריאת מקטע ה-NOTAM מתוך OFP של ארקיע. עובד offline, הכל רץ בדפדפן —
הקובץ לא נשלח לשום מקום.

## הפעלה מקומית
    python3 serve.py      # http://127.0.0.1:8731

## קבצים
| קובץ | תפקיד |
|---|---|
| `index.html` | ממשק + עיצוב |
| `app.js` | חיווט UI, קיבוץ לפי תחנה, רינדור כרטיסים |
| `parser.js` | פרסור מקטע ה-NOTAM + טבלת סיווג החשיבות (`RULES`) |
| `pdfload.js` | PDF → טקסט, שחזור פריסה מקואורדינטות |
| `vendor/` | pdf.js 4.6.82 (מקומי, לא CDN) |

## שני ניבים של עלון NOTAM
ה-OFP מגיע בשני פורמטים, ושניהם נתמכים:

| | ניב A | ניב B (LIDO) |
|---|---|---|
| תאריך | `VALID: 29-JAN-26 1632` | `VALID: 2601291632` |
| מקטעים | `DEPARTURE / DESTINATION AIRPORTS` | `DEPARTURE AIRPORT` + `DESTINATION AIRPORT` בנפרד |
| כותרת עמוד | אין בעמודי ה-NOTAM | `AIZ nnn/...` בכל עמוד |
| שם תחנה | `LLBG /TLV TEL AVIV/BEN GURION` | + סיומת `- DETAILED INFO` |

בגלל ניב B אסור לסיים את מקטע ה-NOTAM בכותרת ה-`AIZ` הראשונה — היא מופיעה בכל
עמוד. המקטע רץ עד סוף המסמך.

## למה שחזור פריסה ולא טקסט רגיל
סדר הקריאה שpdf.js/PDFKit מחזירים מפריד את שורת `VALID:` מה-NOTAM שלה —
שני NOTAMים ואז שני VALID ברצף. `pdfload.js` מסדר את הגליפים לרשת תווים לפי
X/Y ומשחזר את הפריסה החזותית האמיתית. בלי זה ~3% מה-NOTAMים מקבלים תאריך שגוי
או לא מקבלים תאריך בכלל.

## סיווג חשיבות
שלוש רמות ב-`parser.js` → `RULES` (הכלל הראשון שמתאים מנצח, לכן הסדר משמעותי):

- **1 קריטי** — מינימות/OCA, מסלול סגור, המראה מהצטלבות, ILS/LOC, הליך גישה
  מושעה, TWY סגור, PAPI, תאורת גישה, שינוי CAT, שיפוע טיפוס, הגבלת גובה,
  איסור טיסה/מרחב סגור, פעילות צבאית
- **2 חשוב** — GPS/GNSS, אמצעי ניווט U/S, רדאר U/S
- **3 לידיעה** — מכשולים/WIP, ציפורים, חניות, A-CDM, PCR/PCN, שריפות

## סינון
1. **חלון הטיסה** — נשלף מה-OFP (`STD`/`STA`). NOTAM שפג לפני ההמראה או מתחיל
   אחרי הנחיתה מוסתר.
2. **סוג תחנה** — בית / יעד / שדה משנה: כל הרמות. שדות בנתיב ו-FIR: רמה 1 בלבד.
3. **ותק** — NOTAM שה-VALID שלו התחיל בתוך X הימים האחרונים מסומן "חדש"
   (7/14/30, ניתן לשינוי בממשק).

## אימות
נבדק מול שני OFP אמיתיים — IZ213/214 TLV-ATH (74 NOTAMים) ו-IZ271 TLV-BCN
(109). בשניהם: אפס NOTAMים שהוחמצו, אפס עודפים, אפס בלי טווח תוקף.
בדיקת אמת: להשוות את קבוצת ה-IDs שנפרסרו מול כל ID שפותח שורה במקטע.

## שינוי גרסה
לעדכן `APP_VERSION` ב-`app.js` **וגם** `CACHE` ב-`service-worker.js` לאותו מספר.
ה-service worker הוא network-first, כדי שעדכון לא ייחסם ע"י cache ישן. שים לב
ש-`fetch` ב-service worker קורא כברירת מחדל מה-HTTP cache של הדפדפן, ו-GitHub
Pages מגיש עם `max-age=600` — לכן הבקשה חייבת `{cache:'no-cache'}`, אחרת
"network-first" הופך בשקט ל-cache-first ועדכון לא מגיע במשך 10 דקות.
